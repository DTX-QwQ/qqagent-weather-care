# 天气关怀（睡前与起床） v1.1.1

已安装到 `D:\QQAgent\QQ Agent\resources\app\plugins\weather-care\`。
这是本机安装版真正扫描的插件目录（由 `src/plugin-loader.js` 确认）。覆盖旧版，沿用 id，不安装第二份。热重载生效，无需重启。

回到 QQ Agent「插件」页，可看到 **天气关怀（睡前与起床）**。点击设置填写城市即可；城市和作息都可以随时修改，不用编辑代码。所有配置项见 [SETTINGS.md](SETTINGS.md)。设置保存由 QQ Agent 负责，不会覆盖其他插件配置。

## 能做什么

- 设置中的“按时间自动提醒”默认开启；关闭后停止睡前、新一天的定时提醒和补查，聊天关怀与正常天气查询不受影响。重新开启后只处理补查窗口内尚未发送的提醒。

- 默认 **22:00** 睡前、**00:00** 新一天刚开始提醒；也可改为起床前的 **07:00**。
- 检查今天和明天，雨雪、冻雨、雷暴/冰雹、雾、强阵风、偏冷偏热、强紫外线，以及相邻两天最高温或最低温变化达到默认 **5℃** 时提醒。
- 两个设定时间到点固定发送 AI 天气关怀，天气平稳也发送。AI 只负责按人设写内容，不判断是否需要关怀。定时不受“聊天关怀使用 AI”或旧版 `dailyBriefing` 配置影响。
- 聊天出现睡觉、晚安、起床、早安、出门、穿衣、下雨或天气相关词时，读取真实预报，由 AI 结合语境写一句关怀。睡前重点看明天，起床/出门重点看今天；跟随会话人设，可另填语气偏好。
- 自动聊天关怀默认每会话冷却 **30 分钟**、每天最多 **6 次**，防止每提一次都唠叨。显式聊天查询走正常机器人工具流程。
- 有“仅预览”开关；后台定时和聊天关怀只写预览文件，方便检查文案。

## 接收对象和触发方式

**直接读取 QQ Agent 白名单里的群聊和私聊，不另外填写 QQ 号。** 黑名单优先；白名单全空时保持安静。所有会话共用配置的默认城市，聊天工具可查询用户明确指定的其他城市，但不会自动改默认城市。

定时与聊天扫描由插件生命周期启动，是确定性调度；定时强制生成 AI 关怀，聊天的自然语言理解和关怀文案交给 AI，并注册 `weather-care__forecast`、`weather-care__status` 给正常聊天使用。没有修改 QQ Agent 核心或界面代码。

正常聊天已开始处理这条消息时，插件仅添加工具使用提示，不在钩子里联网或发送。未被原有响应档位唤醒的消息，后台在默认等待 20 秒后接手，约每 10 秒检查一次。因此即使普通聊天只响应 @，天气关键词也能触发后台关怀。后台接手前及生成后再次检查已有回复，尽量避免重复。正常聊天这一支最终是否调用工具仍由模型决定。

只处理启用后、最近 3 分钟内的新消息，读取每会话最近 50 条；不重放启用前的晚安或历史聊天。谈及他人、引用台词、无需关怀的闲聊，AI 可以选择沉默。AI 不可用时，只对明确的本人场景使用保守规则关怀。正常聊天和后台在极短时间内并发启动时，仍存在两条回复竞争的极小窗口。

## 天气数据

使用 [Open-Meteo 天气预报](https://open-meteo.com/en/docs)及[地理编码服务](https://open-meteo.com/en/docs/geocoding-api)，无需天气密钥。免费端点适用范围以服务方条款为准。数据是天气模式预报，**不是实况，也不是气象部门官方预警**；不提供专门的台风、沙尘或空气质量告警。

天气缓存最多 15 分钟，跨日重新获取，使用同一配置时区确定日期。温度、降水、风和紫外线关键字段缺失时停止生成，不拿缺值当“晴天”。城市重名时提示候选地点；可在设置填写经纬度精确定位，不猜用户位置。系统 HTTP 代理可用于连接，天气域名仍遵守宿主浏览锁定。Windows 的 Node TLS 连接失败时，使用系统自带 curl/Schannel 兼容读取，仍校验证书和域名；不会改系统代理设置。

天气数据仅供内部判断，定时和后台聊天提醒只发送 AI 润色的一到两句关怀，将重点天气和建议连在一起，例如“明天可能下雨，出门记得带伞呀”。不附天气报表、日期温度概率、标题或来源说明。睡前侧重明天，新一天提醒侧重今天。定时调用禁用工具选择，并请求关闭思考，留足正文预算。空正文、输出截断或格式不合格均按生成失败处理：不发送纯预报、不记为发送成功；记录具体错误，在补查窗口内按一分钟递增、最多五分钟的间隔重试。重试状态持久化，热重载不会立即重复调用。超出窗口不再补发。读取天气失败时记录错误，不编造天气；正常聊天查询会向模型返回具体失败原因。

## 去重和运行条件

电脑、QQ Agent 要保持运行，QQ 在线且宿主未暂停。关机期间无法执行，恢复后只在默认 30 分钟补查窗口内处理。插件关闭/热重载会停止扫描并取消在途请求；已经交给 QQ 的发送无法撤回。

升级保留已发送、未确认和旧版静默记录，不因更新自动重发历史提醒。定时状态在 `data/weather-care/state.json`，聊天状态在 `data/weather-care/chat-state.json`。发送前持久化 pending，超时/结果未确认后不自动重发，避免重复；代价是无法确认的那条提醒可能漏送。状态损坏时暂停对应路径并记录错误，绝不清空记录后重新群发。不要随意删除这两个状态文件。

发送优先使用正常聊天工具取得的共享 `ctx.sender`。尚未取得时，用宿主 `SendQueue` 类排队、限频和去重，再通过本机控制台的发送路由复用现有 QQ 连接和共享聊天存档；不另连 QQ、不直接改聊天 JSON。该后备队列与正常聊天的配额分开计数，插件自身仍有定时去重、聊天冷却及每日次数限制。

定时预览写 `data/weather-care/preview.json`，后台聊天预览写 `data/weather-care/chat-preview.json`。“仅预览”不阻止正常聊天流程回复天气查询。
